# 云服务器部署方案（摆脱本机 8GB 限制）

## 为什么需要云服务器

本机 Docker Desktop 跑在 WSL2 里，`.wslconfig` 的 `memory=8GB` 是硬上限。HA 全套（10 个中间件容器）+ 3 业务 JVM + 压测客户端同时跑，峰值 7.1GB，几乎没有压测余量——再叠加镜像构建就 OOM/daemon 假死。

云服务器是独立 VM，没有 WSL2 这层限制。同样这套栈在 8C16G 上能轻松跑，还能开 K8s。

## 一、选型建议

| 用途 | 配置 | 系统盘 | 参考月费 | 厂商 |
|---|---|---|---|---|
| HA 全套 + 3 服务 + 压测 | 4C8G | 100G SSD | ¥200–400 | 阿里云/腾讯云轻量应用服务器 |
| HA + K8s 单节点 + 压测 | 8C16G | 200G SSD | ¥600–1000 | 阿里云 ECS / 腾讯云 CVM |
| 生产级多机 | 3× 4C8G | 各 200G | ¥1500+ | 云厂商 K8s 托管（ACK/TKE） |

**关键**：选 SSD 云盘（不是高效云盘），Kafka/MySQL 的写入性能差一个数量级。国内厂商选靠近你的地域降低延迟。

## 二、环境初始化（以 4C8G Ubuntu 22.04 为例）

```bash
# 1. 装 Docker + Compose
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker

# 2. 克隆/上传项目
scp -r D:/javaRepo/coupon root@<公网IP>:/opt/coupon
# 或在服务器上 git clone

# 3. 调内核参数（Kafka/Redis 需要）
sudo sysctl -w vm.max_map_count=262144
sudo sysctl -w net.core.somaxconn=65535
echo 'vm.max_map_count=262144' | sudo tee -a /etc/sysctl.conf

# 4. 开放安全组端口
# 8080(网关) 8081-8083(服务) 8848(Nacos) 9092(Kafka) 13308(MySQL) 16381(Redis)
```

## 三、部署 HA 栈

```bash
cd /opt/coupon

# 1. 拉起中间件（MySQL 主从 + Redis 哨兵 + Kafka 3 broker）
docker compose -f docker-compose-ha.yml up -d

# 2. 等健康（约 1 分钟）
docker compose -f docker-compose-ha.yml ps

# 3. 构建业务镜像（多阶段，服务器编译）
chmod +x build-images.sh
REGISTRY=mall TAG=1.0.0 ./build-images.sh

# 4. 启动业务服务（容器化，进入 HA 网络）
docker run -d --name mall-order --network coupon_default -p 8083:8083 \
  -e SPRING_PROFILES_ACTIVE=ha \
  -e SPRING_CLOUD_NACOS_DISCOVERY_ENABLED=false \
  -e "DB_URL=jdbc:mysql://mysql-master:3306/mall_order?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false" \
  -e DB_PASSWORD=root123456 \
  -e "REDIS_SENTINELS=sentinel-1:26379,sentinel-2:26379,sentinel-3:26379" \
  -e REDIS_PASSWORD=mallRedis2026 \
  -e "KAFKA_BOOTSTRAP=kafka-1:9092,kafka-2:9092,kafka-3:9092" \
  mall/order-service:1.0.0
# coupon/seckill 同理，改端口和数据库名

# 5. 验证
curl http://localhost:8081/actuator/health
```

## 四、可选增强（内存充足时）

```bash
# Nacos 3 节点集群（先初始化 nacos_config 库）
docker exec mall-ha-mysql-master mysql -uroot -proot123456 < docker/ha/nacos/mysql-schema.sql
docker compose -f docker-compose-nacos-cluster.yml up -d

# Redis Cluster 3 主 3 从（扩容路径）
docker compose -f docker-compose-redis-cluster.yml up -d
docker exec mall-redis-cluster-1 redis-cli -a mallRedis2026 --cluster create \
  172.29.0.11:6379 172.29.0.12:6379 172.29.0.13:6379 \
  172.29.0.14:6379 172.29.0.15:6379 172.29.0.16:6379 \
  --cluster-replicas 1 --cluster-yes
# 应用改 --spring.profiles.active=cluster
```

## 五、压测验证

```bash
# 从本机连公网 IP 压测（注意安全组放行）
python perf/load_test.py --scenario coupon --base-url http://<公网IP>:8081 \
  --users 200 --duration 60 --fresh-user

python perf/load_test.py --scenario seckill --base-url http://<公网IP>:8082 \
  --users 300 --duration 60 --fresh-user
```

云环境网络和存储都远好于本机 WSL2，`acks=all` 的性能损耗会小很多——本地实测 HA 秒杀 QPS 380（单点 3269），云上预计能到 1000+。

## 六、K8s 生产路径（8C16G 以上）

```bash
# 单节点 K8s（kind/k3d）或多节点托管集群
# 1. 推镜像到仓库
docker tag mall/coupon-service:1.0.0 <your-registry>/mall/coupon-service:1.0.0
docker push <your-registry>/mall/coupon-service:1.0.0

# 2. 一键部署（含 PDB/NetworkPolicy/反亲和）
REGISTRY=<your-registry> k8s/deploy.sh
```

## 七、成本与优化

- **按量付费试用**：先用按量实例跑 1-2 天验证，确认没问题再转包年包月，省 30-50%。
- **停止不用的资源**：Nacos/Redis Cluster 验证完就停，只留 HA 哨兵栈。
- **日志盘分离**：Kafka/MySQL 数据挂独立云盘，避免系统盘 IO 打满。
- **监控告警**：部署 `k8s/alerts.yml` + `alertmanager.yml`，接企业微信/钉钉 webhook。

## 八、已知限制

- 应用层多副本 + K8s 自愈需在真实多机集群验证，单节点 K8s 只能验证部署流程。
- MySQL 主从异步复制有秒级延迟，金融级需 MGR/InnoDB Cluster。
- 云上同样要控制并发容器数——4C8G 塞 HA + K8s + 压测也会紧张，建议 8C16G 起。
