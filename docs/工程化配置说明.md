# 工程化配置说明（Flyway / Lint / CI）

## 一、数据库版本管理：Flyway

### 现状

项目已引入 Flyway 9.22.3（由 Spring Boot BOM 管理），**每个服务只迁移自己的 schema**，符合微服务数据私有权：

```
mall-coupon-service/src/main/resources/db/migration/V1__init.sql    → mall_coupon 库
mall-seckill-service/src/main/resources/db/migration/V1__init.sql   → mall_seckill 库
mall-order-service/src/main/resources/db/migration/V1__init.sql     → mall_order 库
```

### 两种初始化方式（二选一，不要同时用）

| 方式 | 配置 | 适用场景 |
| --- | --- | --- |
| **Docker initdb.d**（默认） | `FLYWAY_ENABLED=false`（默认），沿用 `sql/init.sql` | 本地 demo / HA 验证，空数据卷首次启动 |
| **Flyway 自动迁移** | 环境变量 `FLYWAY_ENABLED=true` | 生产 / 已有库升级，自动记录版本 |

**关键**：Flyway 和 `init.sql` 都会建表，不要对同一个库同时启用。用 Flyway 时，从 compose 里移除 `sql/init.sql` 的 `initdb.d` 挂载。

### 工作方式

- 启动时 Flyway 检查 `flyway_schema_history` 表，只执行未应用过的版本脚本
- `baseline-on-migrate=true`：对已有数据的库也能接入（以当前状态为基线 v1）
- `validate-on-migrate=true`：脚本被篡改会启动失败，防止版本漂移

### 新增迁移

新建 `V2__xxx.sql`（版本号递增），写在对应服务的 `db/migration/` 下。Flyway 按版本号顺序执行，每个版本只跑一次。

> 旧的 `sql/kafka-migration.sql`（加 `stock_bucket`）已合并进 order 服务的 V1，保留文件仅作历史参考，无需再手工执行。

## 二、代码质量：Spotless + Checkstyle + JaCoCo

三个插件配在父 pom，所有服务继承：

| 插件 | 作用 | 命令 | 是否 CI 门禁 |
| --- | --- | --- | --- |
| Spotless | google-java-format 格式检查 | `mvn spotless:check` / 格式化 `mvn spotless:apply` | **否**（存量代码未统一格式） |
| Checkstyle | 命名/坏味道/import 规范（规则见 `config/checkstyle/checkstyle.xml`） | `mvn checkstyle:check` | 是（已通过） |
| JaCoCo | 单元测试覆盖率报告 | `mvn test` 后看 `target/site/jacoco/` | 否（只出报告） |

说明：
- **Spotless 暂不作为 CI 门禁**：存量代码不符合 google-java-format（27 个文件有违规），强制 check 会让所有构建变红。它保留为可选工具——想统一格式时手工跑 `mvn spotless:apply`（会实际改写文件）。
- Checkstyle 规则克制：只查命名、空语句、equals/hashCode、switch default、无用 import 等，LineLength 放宽到 150；实测 `mvn checkstyle:check` 通过。
- JaCoCo 只出报告，不卡构建（当前覆盖率低，设门槛会挡住所有构建）。

## 三、CI/CD：GitHub Actions 模板

`.github/workflows/ci.yml` 是一个**参考模板**：

- 如果项目推到 GitHub，push/PR 时自动跑：`mvn test` → `spotless:check` → `checkstyle:check` → `mvn package`
- 如果项目不在 GitHub（本地或 GitLab/Jenkins），这文件不会执行任何东西，但保留了「这个项目该跑什么检查」的标准定义，需要时照搬 steps 里的命令即可

核心检查命令，任何 CI 平台都能跑：
```bash
mvn -B test
mvn -B checkstyle:check
# mvn -B spotless:check   # 可选，存量代码未格式化前不要当门禁
```

## 四、Flyway 体积

`flyway-core` 约 2–3 MB，打进 fat jar 后总大小增加不到 3%（现有 jar 97–146 MB），运行时内存开销几 MB 级别，可忽略。
